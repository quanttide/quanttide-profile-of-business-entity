# GitHub 活动面板项目用户故事地图

用户画像：需要构建用户每日活动面板并新增扩散/合并指标的研究人员 / 数据工程师。

## 活动一：调研

### 任务：录入数据需求

· 用户要梳理公开平台数据源（用户/项目/提交/合并请求等表）
· 用户要明确目标用户清单
· 用户要以客户的数据字典为准定义变量，不按自己理解设计

## 活动二：谈判

### 任务：定义变量口径

· 用户要定义扩散类指标（全生命周期/一年窗口 × 总扩散/活跃扩散）
· 用户要定义合并拆分指标（自合并 / 外部合并）
· 用户要明确扩散计数来源是样本外扩散，不是样本内互相关联
· 用户要明确活跃判定选对数据通道，避免继承关系假阳性

### 任务：与客户确认口径

· 用户要确认时间窗口边界（如左闭右开）、按 UTC 日历日
· 用户要确认右删失标记（数据有截止日期）
· 用户要确认内部一致性恒等式（拆分之和 = 总量）

## 活动三：实施

### 任务：标准化与过滤

· 用户要用目标清单筛选目标群体，分块扫描项目表确权
· 用户要筛选来源字段命中的扩散记录
· 用户要分块提取合并请求历史，清除空值

### 任务：计算指标

· 用户要构建时间倒排索引，扫描提交记录判定活跃扩散
· 用户要按（用户 × 日期）聚合计算扩散类指标
· 用户要按（用户 × 日期）聚合输出每日自合并/外部合并双维特征

## 活动四：验收

### 任务：查看验证结果

· 用户要看到合并拆分验证报告（自合并/外部合并/悬空样本分布）
· 用户要看到内部一致性验证（恒等式和子集关系逐行成立）
· 用户要导出最终面板数据（含新增指标）

## 活动五：复盘

### 任务：复盘开源

· 用户要复盘 CLI 复现流程的问题（LLM 无进度、契约为空、规格丢字段、review 假阳性）
· 用户要把口径管理经验（以数据字典为准、扩散看样本外、选对数据通道）沉淀为可复用资产
· 用户要把面板构建流程抽象成开源的数据工程模板
