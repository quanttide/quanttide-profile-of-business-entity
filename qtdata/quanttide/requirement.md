# 量潮科技数字化（第一期）— 议事决议数据需求文档

## 业务目标

把飞书知识库中的议事决议数据（提案、会议纪要、部门简报）加工为标准化决议档案，输出治理视图与周会决议汇总，支撑决议"可执行、可追溯、可治理"——每条决议有责任人、有完成期限、可溯源到原始文档。

## 数据范围

- 来源：飞书议事档案知识库（议题 12 类、决议、执行管理节点）
- 形态：提案（5 篇）、会议纪要、部门简报（lark-cli drive +export 导出）
- 规模：单周示例（第 33 周）→ 历史周会批量整理（第 30/31/32 周等）

## 输入要求

数据由量潮数据从飞书采集（lark-cli drive +export 导出提案/会议纪要/简报），客户无需另行提供数据文件。

## 输出期望

- 决议档案：一决议一文件（YAML），对齐决议 schema（id/title/content/owner/due/status/vote/source/evidence/history）
- 索引聚合：index.yaml（统计 + 逾期推导，逾期 = due < today 且未完成）
- 治理视图 JSON：stats/overdue/by_owner/resolutions——客户端可消费
- 周会决议汇总：决议清单 + 质量指标（编号错位/辩论记录/决议落档）

## 约束与假设

- 数据源为飞书知识库，导出需具备 lark-cli 访问权限
- 编号双轨：提案按发布周、会议按召开周编号
- 内部项目定价：0.8 万元（成本法 0.5 万 × 市场法 1.2 万 × 市场价 7 折）
- 质量基线为实验基线：编号错位 100%、辩论记录 20%、决议落档 0 条

## 验收标准

- [ ] 每条决议落库为独立 YAML 档案，schema 对齐
- [ ] 决议可溯源（source/evidence/history 完整）
- [ ] 逾期推导正确：due < today 且未完成即逾期，期限缺失不误报
- [ ] 质量基线可复现：编号错位检测、辩论记录率、决议落档数
- [ ] 治理视图 JSON 通过 schema 校验，客户端可消费
