# SEC 信贷协议提取项目

> 本档案是一个真实数据项目的脱敏复盘记录，记录定位、结构、质量与可复用经验。具体客户信息、私有存储位置和数据规模不在本公开档案中。

## 定位：从公开申报文件中构建可追溯的数据资产

这是一个基于 SEC EDGAR 公开申报文件的数据工程项目：识别信贷协议、修订、延期和补充文件，提取供应链相关文本，并生成可复核、可追溯的结构化结果。

## 核心目标：完成识别、提取、复核和交付闭环

1. 在申报附件层识别目标文件，减少仅按申报标题判断造成的误分类。
2. 从目标文件中提取供应链相关文本，并保留原始文件定位信息。
3. 通过人工复核、异常记录和质量检查提高结果的可解释性。
4. 将原始文件、结构化结果、索引和说明组织成可重复检查的交付包。

## 阶段方法：五阶段项目制

项目按五阶段推进，复盘贯穿始终：

| 阶段 | 项目交付 | 复盘沉淀 |
|------|---------|---------|
| 调研 | 数据需求、目标文件定义 | 文件识别与需求模板 |
| 谈判 | 数据规格、纳入与排除口径 | 分类规则与质量约束 |
| 实施 | 下载、识别、提取和复核流程 | 可复用处理流程 |
| 验收 | 结果索引、质量摘要和交付清单 | 验收检查表 |
| 复盘 | 项目复盘记录 | 工作手册、教程、README |

## 数据结构：原始文件到结果的追溯链

从项目中抽象出的通用结构：

**输入**：

- SEC EDGAR 公开申报文件；
- 申报及附件的基本元数据；
- 目标文件识别和文本提取规则。

**处理流程**：文件下载 → Exhibit 级分类 → 目标文本提取 → 人工复核 → 结果汇总 → 交付打包。

**输出**：

- 目标原始文件；
- 文件级分类和处理索引；
- 供应链相关文本结果；
- 排除文件、相关文件和日期异常辅助记录；
- 处理摘要、交付说明和质量检查结果。

## 数据质量：从真实交付中形成的口径

- **可追溯性**：每条结果都能定位到原始文件和处理记录。
- **分类完整性**：主合同、修订、延期和补充文件按统一规则区分。
- **结果可复核**：自动提取和人工复核状态不能混为一谈。
- **索引一致性**：文件索引、结果文件和处理摘要能够相互核对。
- **异常显式记录**：日期异常、排除文件和相关文件进入独立辅助记录。
- **交付可重现**：交付包有稳定目录、说明和 manifest，解压后可以独立检查。

## 复盘与开源

从项目中沉淀出的可复用经验：

- 公开申报文件处理应在 Exhibit 层完成识别；
- 结果数据必须和原始文件建立稳定的追溯关系；
- 需求、规格和脚本需要共同约束纳入、排除和复核口径；
- 全量运行前应先检查参数、输入输出和小样本结果；
- 交付包的索引和质量摘要与结果文件同等重要；
- 使用外部 LLM 前要确认授权、数据处理边界和密钥配置方式。

可继续发展为：

- 公开申报文件识别工作手册；
- 可追溯文本提取模板；
- 数据交付包目录和 manifest 模板；
- 数据质量验收清单；
- 面向新人使用的项目交接模板。
